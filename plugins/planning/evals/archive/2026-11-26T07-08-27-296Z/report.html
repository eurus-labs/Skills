# Software requirements — export

## SWR-001 — Limit per request

- Statement: The software shall reject an export request for more than 100 reports.
- Rationale: SYS-001 raises the limit from 50 to 100 for every user (DOU-001).
- Traces to: SYS-001
- Type: functional
- Verification criteria:
  - A request for 100 reports by any user succeeds and returns 100 outputs.
  - A request for 101 reports is rejected with an error, and no output is written.
  - A request for 51 reports, which the old limit refused, succeeds.
- Component: `src/exporter.py:8`, `src/exporter.py:33`
- Status: changes existing behavior

## SWR-002 — Owner-only export

- Statement: The software shall export a report only when the requesting user is its owner.
- Rationale: SYS-003 limits export to the owner; the code also allows teammates (`src/exporter.py:19`), and the PO settled "owner only" (DOU-002).
- Traces to: SYS-003
- Type: functional
- Verification criteria:
  - A request by the owner of a report succeeds and returns an output for it.
  - A request by a teammate who is not the owner is rejected with an error, and no output is written for that report.
  - A request by a user on another team who is not the owner is rejected with an error.
- Component: `src/exporter.py:17-19`, `src/exporter.py:39-40`
- Status: changes existing behavior

## SWR-003 — Schedule a nightly export

- Statement: The software shall let a user schedule an export to run every night.
- Rationale: SYS-004 asks that a user can schedule a nightly export. The report set is assumed to be the reports the user could export by hand (analysis assumption).
- Traces to: SYS-004
- Type: functional
- Verification criteria:
  - After a user schedules an export, the schedule exists and is shown as active for that user.
  - A user cannot schedule an export for a report they do not own; the request is rejected with an error and no schedule is created.
- Component: new: a scheduling capability beside `src/exporter.py` (none exists today)
- Status: new

## SWR-004 — Run scheduled exports nightly in UTC

- Statement: The software shall run each scheduled export once per night, with the night determined in UTC.
- Rationale: SYS-004 asks for a nightly run; the PO fixed the time zone as UTC (DOU-005).
- Traces to: SYS-004
- Type: functional
- Verification criteria:
  - With a schedule active, the export runs exactly once in each UTC night and its outputs are written.
  - For a user whose local time zone differs from UTC, the run time follows UTC, not the user's local time.

- Component: new: a scheduling capability beside `src/exporter.py`
- Status: new

## SWR-005 — Tell the user when a scheduled export fails

- Statement: The software shall notify the user when a scheduled export fails.
- Rationale: SYS-004 and the PO's answer: "tell the user" on failure (DOU-005).
- Traces to: SYS-004
- Type: functional
- Verification criteria:
  - When a scheduled run fails (for example the export raises an error), the user receives a notification identifying the failed export.
  - When a scheduled run succeeds, no failure notification is sent.
- Component: new: a scheduling capability beside `src/exporter.py`
- Status: new

## SWR-006 — Retry a failed scheduled export the next night

- Statement: The software shall run a failed scheduled export again on the next night.

- Traces to: SYS-004
- Type: functional
- Verification criteria:

  - After a failed run on night N, no further run happens on night N before N+1 (no immediate retry).

- Component: new: a scheduling capability beside `src/exporter.py`
- Status: new

## SWR-007 — Audit log entry per export

## Open points

These are not covered by a DOU, and I did not ask the PO (not available). They are my assumptions, to confirm.

- **Nightly time of day.** DOU-005 gives the zone (UTC) but not the hour. SWR-006 therefore says "a fixed time", configurable; the value is unspecified. A test needs a number.
- **Notification channel (SWR-007).** "Tell the user" does not say how (email, in-app, other).
- **Retry limit (SWR-008).** The PO said "run it again the next night". I did not add a cap on repeated failures, or a retry on the retry's failure beyond the following night.
- **Scheduled export contents (SWR-005, SWR-009).** The report set, format and owner-only check at run time follow the analysis assumption (PO owns the risk); unconfirmed. Whether a schedule continues if the user later loses ownership is not stated.
- **SWR-011 environment.** The 30-second target has no stated hardware or load; it should be fixed before the test is written.
- **Empty reports.** The code rejects a report with no rows (`src/exporter.py:37-38`); no requirement covers this. Left unchanged and not derived.
