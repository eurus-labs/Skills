## Findings

- **R-002** — conflicting: the code lists `pdf` as supported (`src/exporter.py:9`) but writes CSV text under a
  `.pdf` name (`src/exporter.py:23-26`). The requirement is unchanged, so this is an existing gap. See OP-005.
- **R-003** — ambiguous: "at most 100 reports in one request" does not say whether the limit is the same for all
  users or roles. Treated as an assumption, see below.

  request, or only that report. The code rejects the request but leaves earlier files written. See OP-006.
- **R-005** — conflicting: "Only the owner of a report can export it" against the code, which also allows
  teammates (`src/exporter.py:18-19`). Also ambiguous: "rejected with an error" gives no error type, code or
  message. See OP-001.
- **R-006** — missing: v1 required the audit log and v2 omits it without saying it is dropped. The code still
  writes it (`src/exporter.py:42`). See OP-002.
- **R-007** — ambiguous / missing: "schedule an export to run every night" does not define the time or time zone,
  which reports and format, who can schedule, how a user cancels or lists schedules, what happens when a run
  fails or the report is then empty or no longer owned, whether the 100-report limit applies, and whether the
  run is audited. See OP-003.
- **R-008** — untestable / non-functional gap: "large", "quickly" and "should" carry no size, time or
  percentile. See OP-004.
