## Review summary
`app.py` is an account service module with user lookup, order search, login redirect, export download, password hashing, account deletion and receipt formatting. **Verdict: needs work.** It has several exploitable security flaws, and I would not merge it. The module docstring says the file is an intentionally vulnerable fixture ("DO NOT DEPLOY"). I reviewed it as production code anyway, since you asked for a pre-merge review. Scope was all of `app.py`, with no diff or base revision available. The repository has no `AGENTS.md`, `CONTRIBUTING.md`, Copilot instructions or review checklist.

## Findings

### Blocking
1. **`app.py:28`** — issue: SQL injection in `find_user` (CWE-89).
   `username = "x' OR '1'='1"` returns an arbitrary user row. A UNION payload can read any table in the database.
   Use a parameterized query: `db.execute("SELECT ... WHERE username = ?", (username,))`.

2. **`app.py:36-39`** — issue: SQL injection in `search_orders` through both `customer_id` and `status` (CWE-89).
   `status = "' OR 1=1 --"` returns every customer's orders. `customer_id` is unquoted, so it is injectable even if it is a number.
   Use `?` placeholders for both values.

3. **`app.py:62-69`** — issue: `delete_account` has no authorization check (CWE-862).
   The docstring says only an administrator may delete an account that isn't their own, but `actor` is never read. Any caller can delete any account.
   Check `actor.role == "admin" or actor.id == account_id` before the `DELETE`, and return or raise on failure. Add a test for the denied path.

4. **`app.py:50-54`** — issue: path traversal in `download_export` (CWE-22).
   `filename="../../etc/passwd"` makes `os.path.join` produce a path outside `EXPORT_ROOT`. An absolute `filename` such as `/etc/passwd` discards `EXPORT_ROOT` entirely.
   Resolve with `os.path.realpath` and require `os.path.commonpath([root, path]) == root`. Alternatively, accept only a known basename.

5. **`app.py:44-47`** — issue: open redirect in `login_redirect` (CWE-601).
   `?next=https://evil.example` sends a freshly authenticated user off-site, which makes phishing links look legitimate. `//evil.example` also bypasses a naive "starts with /" check.
   Allow only relative paths: no scheme or netloc, starting with a single `/`. Otherwise fall back to `/dashboard`.

6. **`app.py:57-59`** — issue: unsalted MD5 for password storage (CWE-327, CWE-916).
   If the database leaks, MD5 hashes crack at billions per second. Identical passwords also produce identical hashes, so rainbow tables work.
   Use `hashlib.scrypt`, or argon2 or bcrypt, with a per-user salt. Compare hashes with `hmac.compare_digest`.

7. **`app.py:16`** — issue: hardcoded session signing key (CWE-798).
   Anyone with read access to the repository can forge signed sessions. The key is also in git history, so rotate it once it is removed.
   Load it from the environment or a secrets manager, and fail at startup if it is missing.

### Should fix
1. **`app.py:25-31`** — suggestion: `find_user` leaks the connection if `execute` raises.
   A DB error skips `db.close()`, so a failing query repeated over time exhausts file handles. Use `try/finally` or `contextlib.closing`.

2. **`app.py:62-69`** — suggestion: `delete_account` always returns `True`, even when no row matched.
   Deleting a non-existent ID reports success. Check `cursor.rowcount` and return its result.

3. **`app.py:72-79`** — suggestion: `format_receipt` indexes `order["items"]` and `item["price"]` directly.
   A `None` price raises `TypeError` mid-render. Floats for money also invite rounding drift, so prefer `Decimal` or integer cents. No input validation or tests exist.

### Nits
1. **`app.py:50-54`** — nit: the docstring says "Stream", but the function reads the whole file into memory. Either stream it or correct the docstring.
2. **`app.py:21-22`** — nit: the DB path `"accounts.db"` is relative to the current working directory and is not configurable.

## Not reviewed
- **Callers and framework wiring.** Nothing else in the directory shows how `request` and `actor` are built, so I couldn't judge CSRF (CWE-352) or authentication for these endpoints.
- **Tests.** The directory has none. I didn't run `detect_stack.py`, so test coverage was not assessed.
